# 2026-09-30 — v0.4.0 response incident qualification update

This is a source-candidate incident record, not a release approval or a
publication announcement. The reported symptom was an auto or explicitly
selected model turn that repeated output or stopped responding without a
visible liveness cue.

## Diagnosis

- npm `aether-agents` `latest` was still 0.3.2 on September 30 while this
  source candidate was 0.4.0. The published package does not contain the
  candidate fixes.
- On the investigated Windows device, both `aether` and `aether-agent` resolved
  through global npm shims to a junction targeting a separate, older 0.4.0
  source checkout. Running either command did not run the candidate being
  verified here.
- Node 24 on that device rejected the hosted API certificate chain with
  `UNABLE_TO_VERIFY_LEAF_SIGNATURE`. A Windows HTTP client reached the same
  API, and Node reached it with `--use-system-ca`. The rebuilt candidate now
  adds Windows system certificate authorities to Node's existing trusted
  roots at CLI startup; its secret-free auth status verified the saved session
  without a special launch flag. TLS verification remains enabled.

These installation and trust-store findings explain why local source tests
alone could not establish that the command on `PATH` would answer. The response
path also needed liveness and repeated-output handling after a turn began.

## Candidate changes and observed behavior

The source changes add a pre-response pulse, keep a liveness cue
through non-answer stream metadata, surface later silence without overwriting
streamed answer text, show an initial status for coding turns, and stop repeated
model text from indefinitely extending the meaningful-progress deadline.
Terminal-session heartbeat rendering is connected to real heartbeat events.
Focused regression coverage covers those paths.

After the Windows CA bootstrap, a rebuilt 0.4.0 source CLI ran
`node dist/src/main.js --json chat "Reply with the single word READY."` without
`--use-system-ca`. The authenticated turn received streamed text, a terminal
`done` frame and a successful turn outcome, and the process exited 0. This
live result preceded the final response-path edits. It proves that one hosted
chat turn completed on this device, not that every mode or packaged interactive
path is qualified.

After those edits, the rebuilt source ran one-shot authenticated chat from the
broad Windows home directory and returned an answer with exit 0. In a headed
terminal, `aether agent` in Auto mode showed its thinking animation, returned
an authenticated answer, accepted `/exit`, and exited 0. An isolated, signed-out
Auto configuration selected local Ollama and returned an answer with exit 0.

The candidate npm tarball was installed into an isolated prefix without
lifecycle scripts or network access. That installed `aether` reported 0.4.0;
from the broad Windows home directory it completed authenticated one-shot
chat and a headed Auto-mode `aether agent` turn with visible animation, then
accepted `/exit`. These are real device canaries for the response incident,
not final protected CI or publication evidence.

A separate `doctor --live` dev-session probe reached the server but received
`HTTP 403: agent dev sessions disabled`. That is a server-side refusal of the
non-billable dev-session probe; it is not a successful coding-agent session or
evidence of a client TLS failure. No dev-session enablement is claimed here.

## Remaining qualification

The final source commit still needs its full local and protected CI checks,
CodeQL, release-truth and `verify:production -- --tag v0.4.0` results. The
coding-agent path and relevant model modes need their own final-build checks;
the observed dev-session 403
must remain an explicit server limitation. The existing Cloud, ATS, browser
and legal gates in the [v0.4.0 operator packet](OPERATOR-PACKET-v0.4.0.md)
also remain in force.

No v0.4.0 npm or PyPI publish, tag, GitHub Release, provenance, or registry
dist-tag change is established by this record. The globally linked device
install must be reconciled with a verified build before its `aether` command
can serve as release evidence.
